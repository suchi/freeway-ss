---
description: 承認済みPRのマージ・ブランチ削除・mainの同期
argument-hint: <PR番号> [バージョンタグ]
---

$ARGUMENTS の第1引数で指定されたPRを、最終チェックのうえマージする。

前提条件 — すべて確認し、1つでも満たさなければマージせず停止して報告する:

1. レビュー完了: 未解決スレッドがなく、最新の敵対的セルフレビュー(AGENTS.md「PR・レビュー・マージ」)で新規指摘なし。
2. CIの全ジョブがグリーン。
3. ユーザー承認(ユーザーによるこのコマンドの実行は承認とみなす)。

手順:

1. PR本文のチェックリスト(CIのグリーン化・ユーザーの実機確認など)を実態に合わせて更新する(AGENTS.md「PR・レビュー・マージ」)。
2. `gh pr merge <PR番号> --merge --delete-branch`
3. 本文の図のリンクと詳細設計へのリンクを、作業用ブランチから`main`に直す(AGENTS.md「PR・レビュー・マージ」)。
4. `git checkout main && git pull`
5. バージョンタグ指定があれば: マージコミットに`git tag <バージョン> <SHA>`を付け、`git push origin <バージョン>`でプッシュする。タグのプッシュはリリース(公開)を起動するので、このタグについてユーザーの承認を得ているときだけ行う(AGENTS.md「リリース」)。作業環境からタグのプッシュが通らないときは、コマンドを示してユーザーに手元からプッシュしてもらう。公開されたら、`docs/handoff.md`の「リリースの検証の手順」で成果物を確かめる。
6. ローカルのフィーチャーブランチが残っていれば削除し、日本語で完了報告する。
