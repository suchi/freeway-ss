# Phase 7.4 詳細設計: トラック

- ステータス: 実装済み(実機確認待ち。[#19](https://github.com/suchi/freeway-ss/pull/19))
- 日付: 2026-10-26
- 親計画: [Phase 7 計画](0007-phase7-optional-features.md)

本書は、Phase 7.4を別のセッションや別の実装者が引き継げるように、設計と作業手順をまとめたものである。実装は本書とAGENTS.mdに従う。本書と実装が食い違った場合は、実装を変える前に調整役のセッションに伝える(AGENTS.md「複数セッションでの分担」)。

## 1. 目的と完了条件

目的: 他車の一部を、マーカーランプを付けた大型トラックにする。本家のREADMEに挙がっているが、本家のコードにはまだない要素なので、独自に設計する。

2026-10-26にユーザーと決めたこと:

- 灯火の見た目: 既定は日本の大型トラック風。北米の大型トラック風も設定で選べる
- 対象: 同じ車線の先行車・対向車・追い越していく車のいずれもトラックになりうる
- 割合と設定: 約5台に1台。設定で出し入れでき、既定は出す

完了条件:

- 設定画面に「トラック」の選択(なし・日本風・北米風。既定は日本風)があり、OKで保存される(日本語と英語)
- 先行車・対向車・追い越していく車の約5台に1台がトラックになり、3.3節の灯火で描かれる
- 「なし」のときは、今と同じ交通になる
- トラックの割合と灯火の配置、設定値の検証と保存のテストがある
- ユーザーが実機で確認する
- ワークスペースのバージョンが`1.4.0`になっている(このPRの最初のコミットで実施済み)

## 2. 前提(Phase 7.3までの状態)

- 他車は`freeway-core`の`traffic.rs`にある。種類は、同じ車線の先行車(`Lead`、5台)・追い越し車線の車(`Passing`、6台)・対向車(`Oncoming`、14台)。車ごとの値は、シード・車の番号・置き直した回数から作るハッシュで決まる
- 灯火は`CarLight { d, lateral, height, size, color, alpha, glare }`の列として出し、場面が道路の光と同じ方法で投影して描く
  - 先行車・追い越し車: 尾灯2つ(高さ0.8 m、左右±0.7 m)と、ブレーキ時のハイマウントストップランプ(高さ1.15 m)
  - 対向車: 前照灯2つ(高さ0.65 m、左右±0.7 m)と、近いときのまぶしさ(`glare`)
- 横の位置は、左側通行で自車が左車線にいるときの値で持ち、右側通行では投影で反転する
- 設定は`Settings`とレジストリの`REG_DWORD`。画面の文字列は`i18n.rs`の表(ADR-0007)。言語の選択にはドロップダウンを使っている

## 3. 設計

### 3.1 設定

- `freeway-core`に`TruckStyle`(`None`・`Japanese`・`NorthAmerican`)を加え、`Settings`に`trucks`(既定`Japanese`)を加える
- レジストリ値は`Trucks`(`REG_DWORD`。0: なし、1: 日本風、2: 北米風)。0〜2以外は既定値(日本風)にする
- `SceneConfig`に`trucks: TruckStyle`を加える(トラックは場面の一部)
- 設定画面に、ラベルとドロップダウン(`CBS_DROPDOWNLIST`)を加える。言語のドロップダウンと同じ作りにする。項目の文字列は`i18n.rs`の表に加える

| キー | English | 日本語 |
| --- | --- | --- |
| トラックのラベル | Trucks: | トラック: |
| なし | None | なし |
| 日本風 | Japanese style | 日本風 |
| 北米風 | North American style | 北米風 |

### 3.2 どの車をトラックにするか

- 車を置く(置き直す)たびに、その車がトラックかどうかをハッシュで決める。確率は5分の1(定数)。設定が「なし」なら常に普通車
- 先行車・追い越し車・対向車のどれにも適用する
- トラックの速さ: 先行車のトラックは普通の先行車より少し遅く(例: 自車の0.80〜0.90倍)、追い越していくトラックは普通の追い越し車より速度差を小さくする(例: 半分)。対向車の速さは普通車と同じでよい
- 車体の大きさ: 長さ12 m、幅2.5 m、高さ3.6 m(灯火の位置の目安。車体そのものは描かない)

### 3.3 灯火

灯火の位置は、トラックの後端(先行車・追い越し車)または前端(対向車)を基準にした、横・高さ・前後のずれで決める。横のずれは車体の中心から測る。色は、赤(尾灯の`TAIL_RED`)、白(前照灯の`HEADLIGHT_WHITE`)、橙(例: 255, 150, 30)。

日本風:

| 見える向き | 灯火 | 位置 |
| --- | --- | --- |
| 後ろ | 尾灯(ブレーキで明るく) | 高さ1.0 m、左右±1.05 m |
| 後ろ | 後部上側端灯(赤) | 高さ3.4 m、左右±1.15 m |
| 横 | サイドマーカー(橙) | 高さ0.9 m、車体の自車に近い側の側面に、後端から前へ1.8 mおきに6〜7個 |
| 前 | 前照灯 | 高さ0.9 m、左右±0.9 m |
| 前 | 前部上側端灯(橙) | 高さ3.3 m、左右±1.15 m |

北米風:

| 見える向き | 灯火 | 位置 |
| --- | --- | --- |
| 後ろ | 尾灯(ブレーキで明るく) | 高さ1.0 m、左右±1.05 m |
| 後ろ | 識別灯(赤、3個) | 高さ3.5 m、中央に0.3 mおき |
| 後ろ | 車幅灯(赤) | 高さ3.5 m、左右±1.2 m |
| 横 | サイドマーカー | 高さ1.0 m、側面の前端近く(橙)と後端近く(赤)の2個 |
| 前 | 前照灯 | 高さ0.9 m、左右±0.9 m |
| 前 | 屋根の灯火(橙、5個) | 高さ3.0 m、運転席の屋根の上に左右に並ぶ(±0.9 mの範囲に等間隔) |

- 先行車・追い越し車は、後ろと横の灯火を出す。対向車は、前と横の灯火を出す
- 横の灯火は、車体の側面のうち、自車に近い側に置く(自車から見える側)。真後ろの先行車では、横の灯火は尾灯の近くに重なって見え、カーブでは列として見える
- 普通車と同じく、遠くでは薄くなる(先行車は`TAIL_RANGE`)。上側の小さな灯火は、尾灯より暗く小さくする
- ブレーキでは、普通車と同じく尾灯が明るくなる。トラックにはハイマウントストップランプを付けない
- 対向車のまぶしさ(`glare`)は、普通車と同じ扱いにする

### 3.4 互換性

- 「なし」のときの交通(車の数・位置・速さ・灯火)は、今と同じにする。トラックかどうかのハッシュは新しいソルトを使い、既存の乱数列を変えない

### 3.5 実装で決めた値

設計に具体的な値がなかった部分は、次のとおり実装した。

- トラックの判定: 置くたびに、ソルト17のハッシュが`0.2`未満ならトラックにする。設定が「なし」なら引かない
- 速さ: 先行車のトラックは自車の0.80〜0.90倍(普通車は0.85〜0.95倍)。追い越すトラックの速度差は普通車の半分(1〜5 m/s)。対向車は普通車と同じ
- 基準位置: 灯火の前後の位置は、車体のうち自車に向いた端(先行車・追い越し車は後端、対向車は前端)を基準に、そこから遠ざかる向きに測る。車体の長さは12 m
- 側面: 横のずれは車体の中心から1.25 m(幅2.5 mの半分)。自車の車線の先行車には「近い側」がないため、右側(追い越し車線の側)に置く。カーブでの見え方は目視で確かめる
- 日本風: サイドマーカーは自車に向いた端から1.8 mおきに7個。上側の端灯は後ろ向きが赤(高さ3.4 m)、前向きが橙(高さ3.3 m)
- 北米風: サイドマーカーは前端から0.5 mの橙と、後端から0.5 mの赤。識別灯は中央と±0.3 m、屋根の灯火は±0.9 mの範囲に0.45 mおき
- 大きさと明るさ: 尾灯と前照灯は普通車と同じ。上側の灯火とサイドマーカーは大きさ0.05 m、明るさは尾灯・前照灯の半分
- 視界の端: 車体に沿って並べた灯火のうち、距離が視界の外になるものは出さない
- まぶしさ: 普通車と同じ式で、高さだけ前照灯に合わせて0.9 mにする
- 設定画面: トラックのラベルとドロップダウンを「山並み」の下、言語の上に置いた。ダイアログの高さは172から192に広げた

## 4. テスト

`freeway-core`(Linux・WindowsのCIで実行):

- 設定: `Trucks`の既定値が日本風、0〜2の対応、範囲外は既定値。`scene_config`に引き継がれる
- 割合: 多数のシードと置き直しで、トラックの割合が5分の1に近い(許容範囲を決めて統計的に確かめる)。3種類の車のどれにもトラックが出る
- 「なし」: どのシードでもトラックが出ない。灯火の列が、この変更の前と同じになる(既存のテストが通る)
- 灯火: 日本風と北米風で、3.3節の数・色・高さの灯火が出る(先行車・追い越し車・対向車それぞれ)。サイドマーカーが自車に近い側にある
- 長時間の健全性: 既存の1時間のテストが、トラックを含めても通る

`freeway-scr`(WindowsランナーのCIで実行):

- レジストリ: `Trucks`を書いて読み戻すと同じ値。値がない・範囲外なら既定値
- 文字列の表のテストが、追加したキーでも通る

見た目は、ユーザーの実機確認で見る。

## 5. 実機での確認(調整役がユーザーに依頼する項目)

- 先行車のトラックの後ろ姿(尾灯・上部の灯火)と、カーブでサイドマーカーの列が見えること
- 対向車のトラックとすれ違うときに、橙のサイドマーカーが流れること
- 追い越していくトラック
- 日本風と北米風の違いと、「なし」で今と同じになること
- 設定画面のドロップダウン(日本語と英語)と、DPI 150%などでのレイアウト
- トラックの割合(約5台に1台)が自然か

## 6. 作業手順

実装用セッション:

1. ワークスペースのバージョンを`1.4.0`に上げる(このPRの最初のコミットで実施済み)
2. `freeway-core`の`Settings`・`SceneConfig`・文字列の表に項目を加え、テストを加える
3. `traffic.rs`に、トラックの判定・速さ・灯火(日本風・北米風)を、テストとともに実装する
4. レジストリの`Trucks`と、設定画面のドロップダウンを加える
5. README(設定の表)・利用者向けの説明書(`packaging/README.md`。日本語と英語)・実装計画の進捗表・0007の表を更新する
6. AGENTS.mdの検証コマンドをすべて実行する(Windowsターゲットのclippy、`ufo-demo`付きのclippyも含む)
7. 1コミット1論理変更でコミットし、プッシュする。コミットの種類はAGENTS.mdの許可リストから選ぶ
8. 敵対的セルフレビューを行い、指摘と対応をPRコメントに記録する
9. CIの成功を確認したら、PRの監視を外して調整役のセッションに完了を報告する

調整役:

10. ユーザーの実機確認とマージの承認を得て、マージする。`v1.4.0`のタグはユーザーが手元からプッシュする
