# ADR-0007: localize-ui-strings-in-code

- ステータス: 採用
- 日付: 2026-10-26

## 背景

Phase 7.2で、設定画面とエラーメッセージを日本語と英語に対応させる。2026-10-26のユーザー判断で、表示する言語は設定画面で選べるようにする(自動・English・日本語。自動はWindowsの表示言語に従う)。これまで、設定画面の文字列はリソース(`freeway.rc`のダイアログ100)に英語で書き、エラーメッセージはコードに英語で書いていた。

## 決定

画面に出す文字列は、言語ごとの文字列の表として`freeway-core`のコードに持つ。設定画面は今の1つのダイアログテンプレートを使い、表示するときと言語を切り替えたときに、各コントロールの文字列をコードから設定する。エラーメッセージも同じ表から取る。

検討した選択肢:

- リソースに言語別のダイアログと文字列表を置く方式(`.rc`の`LANGUAGE`ブロック): Windowsの標準的なやり方で、表示言語に従うだけならコードがほとんど要らない。しかし、表示言語と違う言語を選ぶには、スレッドの優先UI言語を切り替えてからダイアログを開き直す必要がある。設定画面の中で言語を切り替えたときに、その場で表示を変えるのも難しい。また、`.rc`の日本語の文字コードの扱い(`#pragma code_page`)と、言語ごとにレイアウトを二重に保守する手間が増える
- コードに文字列の表を持つ方式(採用): 言語の切り替えをその場で反映できる。文字列の表はOSに依存しないので、Linuxでも、すべての言語に訳がそろっていることをテストできる。ダイアログのレイアウトは1つで、どちらの言語の文字列も収まる大きさにする

## 結果

- メリット: 設定画面で選んだ言語を、その場で表示に反映できる。訳の抜けをテストで検出できる。リソースの文字コードの問題を避けられる
- デメリット・受け入れたトレードオフ: ダイアログテンプレートの文字列(英語)は、コードで上書きするまでの既定値として残る。レイアウトは、長いほうの言語に合わせる必要がある
- 将来の見直し条件: 対応する言語が増えて、言語ごとにレイアウトを変える必要が出たとき
