# ADR-0008: span-monitors-as-one-scene

- ステータス: 採用
- 日付: 2026-10-27
- 補足: [ADR-0003: render-independent-scene-per-monitor](0003-render-independent-scene-per-monitor.md) の決定は、設定「複数のモニターを1つの画面として描く」がオフの間は、そのまま有効である。ADR-0003は非推奨にしない

## 背景

ADR-0003は、モニターごとに独立した場面を描くと決めた。v1.16.0で、複数のモニターを1つの画面とみなして、景色をモニターにまたがってつなげるオプションの要望を受けた(ADR-0003の見直し条件「モニター間でつながった表示の要望がある場合」に当たる)。ADR-0003が挙げた懸念は、消失点が1つになることと、解像度・DPIの違うモニターの扱いである。

## 決定

設定(`SpanMonitors`)またはコマンドライン(`/span`・`/nospan`)でオンにしたときに限り、次のように描く。オフのとき、モニターが1台のとき、プレビューと`/window`は、ADR-0003のとおりに描く。

- 場面は1つにする。時間も1つで、`Scene::update`は1フレームに1回だけ呼ぶ
- すべてのモニターを囲む長方形(仮想画面)を1つの画面とみなす。焦点距離は、仮想画面の大きさから、1画面のときと同じ式で決める。消失点は主モニターの中央に置く
- 窓はモニターごとに作る。各窓は、同じ場面のうち自分のモニターに当たる部分を、仮想画面の座標を窓の左上だけずらして描く。見えない部分の描画は省く
- 座標は、物理的な画素の座標で計算する。DPIの違いは、寸法の換算(光の最小の大きさなど)にだけ効かせ、その値は主モニターのものを場面全体で使う。そうしないと、モニターの境目で光の大きさが食い違う
- モニターのない部分(L字の並びのすき間など)は描かない
- 速度計と操作の案内は、主モニターの窓にだけ、1画面のときと同じ位置と大きさで出す

検討した選択肢と選ばなかった理由:

- 窓1つで仮想画面全体を覆う: 窓が1つで済むが、モニターごとのリフレッシュレート・DPI・垂直同期が1つの描画に縛られる。モニターのない部分も描くことになる。
- モニターごとの独立した場面を残し、つなげない: ADR-0003のままで、要望を満たさない。
- 消失点を仮想画面の中央に置く: 主モニターから外れた位置に道路の先が来る。ユーザーの指定(主モニターの中央)に合わない。

## 結果

- メリット: モニターをまたいで景色がつながる。窓がモニターごとにあるため、DPI・リフレッシュレート・モニター間のすき間を、これまでどおりに扱える。
- デメリット・受け入れたトレードオフ: 1つの場面をモニターの数だけ描くため、描画の負荷は(見えない部分を省いても)モニターの数に応じて増える。主モニターが仮想画面の端にあるときは、消失点の反対側の絵が広く、同じ側の絵は画面の外になる。
- 将来の見直し条件: 3台以上のモニターで滑らかに動かない場合。
