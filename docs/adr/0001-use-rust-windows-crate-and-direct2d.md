# ADR-0001: use-rust-windows-crate-and-direct2d

- ステータス: 採用
- 日付: 2026-10-26

## 背景

本プロジェクトはmhatta氏のnightfreeway(ブラウザのCanvas 2Dアニメーション)と似た挙動・見た目のWindowsスクリーンセイバーを作る。AGENTS.mdは、言語とエコシステムを「2026年10月現在で最も一般的かつオープンソースで誰でも利用可能なもの」から選び、リリースバイナリを「配布しやすい形」にすることを求めている。また、アルゴリズムや実装方法は言語やエコシステムに合わせて独自に作成する。

スクリーンセイバーは単一の`.scr`(実行ファイル)として配布されるため、ランタイムの別途インストールが不要で、ファイルが小さいことが望ましい。描画は数千個の光点を加算合成で重ねる2D描画が中心である。

## 決定

言語にRust、Windows APIバインディングにMicrosoft公式の`windows`クレート(`microsoft/windows-rs`、MIT OR Apache-2.0)、描画にDirect2D(Direct3D 11・DXGIスワップチェーン経由)を使う。

- 加算合成はDirect2D 1.1の`D2D1_PRIMITIVE_BLEND_ADD`(Windows 8以降)で行う。本家の`globalCompositeOperation = 'lighter'`と同じ考え方で描ける
- OS非依存のシーン計算を`freeway-core`クレート、Windows固有部分を`freeway-scr`クレートに分け、ロジックをLinuxでもテストできるようにする
- CRTを静的リンクし、ランタイム不要の単一`.scr`として配布する

検討した選択肢と選ばなかった理由:

- C# / .NET 10 + Windows Forms + Direct2Dバインディング: 自己完結型の単一ファイル発行でランタイム不要の単一exeは作れる。しかしWindows FormsはNative AOT・トリミングに公式対応しておらず、ランタイムとフレームワークライブラリを丸ごと含むため配布サイズが大きい。サイズ削減のために圧縮を有効にすると、起動ごとにメモリ上での展開が必要になる
- C++ + Win32 + Direct2D: 資料は最も多いが、標準的なツールチェーン(MSVC)がOSSではなく、メモリ安全性とビルド構成の管理コストが高い
- WebView2/Electron等で本家HTMLを包む: 本家の実装をそのまま使うことになり独自実装の方針に合わない。プレビュー(`/p`)の子ウィンドウ描画と配布サイズにも難がある
- Rust + `wgpu`: クロスプラットフォームだが、2D中心の描画には抽象度が高く、バイナリも大きくなる

## 結果

- メリット: ランタイム不要で小さな単一`.scr`を配布できる。描画ロジックの大半をOS非依存にしてユニットテストできる。言語・ツールチェーン・バインディングがすべてOSSで無償
- デメリット・受け入れたトレードオフ: 設定画面をWin32 API(ダイアログリソース)で作るため、GUIフレームワークよりコード量が増える。Win32/COM呼び出しに`unsafe`が増える
- 将来の見直し条件: Direct2Dで性能目標(4Kで60fps)を満たせない場合、または設定画面の複雑化でWin32での実装コストが見合わなくなった場合
