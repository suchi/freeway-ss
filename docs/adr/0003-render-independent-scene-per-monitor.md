# ADR-0003: render-independent-scene-per-monitor

- ステータス: 採用
- 日付: 2026-10-26

## 背景

スクリーンセイバーは複数モニタ環境でも全画面を覆う必要がある。モニタごとに解像度・DPIが異なる場合があり、本家nightfreewayは1つの画面(ブラウザのウィンドウ)を前提とした透視投影で描いている。

## 決定

モニタごとに全画面ウィンドウを作り、それぞれで独立した場面(独立した道路・交通・背景)を描画する。各ウィンドウは自身のモニタのDPIと解像度に合わせて描画の寸法を換算する。

検討した選択肢と選ばなかった理由:

- 全モニタを1つの広い画面として描画: 透視の消失点が1つになり、モニタのベゼルをまたぐと道路が歪んで見える。解像度・DPIの異なるモニタの組み合わせで扱いが複雑になる
- プライマリモニタのみ描画し他は黒: 実装は最も簡単だが、サブモニタが単なる黒画面になり見栄えが劣る

## 結果

- メリット: 各モニタで本家と同じ構図になる。モニタごとのDPI差を自然に扱える
- デメリット・受け入れたトレードオフ: モニタの数だけ描画とシミュレーションの負荷が増える。モニタ間で場面はつながらない
- 将来の見直し条件: 複数モニタで性能目標を満たせない場合、またはモニタ間でつながった表示の要望がある場合
